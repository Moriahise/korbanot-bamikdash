      So funktioniert die Sammlung

      Diese Datei gehört in denselben Ordner wie Ihre Liedseiten, Klang- und Videodateien. Die Karten verweisen auf die Dateinamen daneben.

      Über Niggun aufnehmen legen Sie HTML-Seiten, .wav, .mp3, .mp4 und .webm ab — auch alles auf einmal. Dateien mit gleichem Namen finden von selbst zusammen: Schirat.html, Schirat.wav und Schirat.mp4 werden eine Karte.

      In der Abspielleiste: ⤨ Zufall mischt die Reihenfolge, ⟲ Stück wiederholt das laufende Lied. Pfeiltasten ←/→ springen 10 Sekunden, mit Umschalttaste zum vorigen/nächsten Stück, die Leertaste hält an.

      Ein Klick auf den Titel oder auf Seite öffnet den Liedtext im Lesefenster — die Wiedergabe läuft dabei weiter, Sie können also mitlesen.

      Über ＋ Liste auf jeder Karte stellen Sie Playlists zusammen; die Abspielleiste folgt dann der Reihenfolge der Liste. Hinweise schlägt Zusammengehöriges vor — nach Namen und Merkmalen sofort, inhaltlich über einen eigenen KI-Schlüssel. Übernommen wird nur, was Sie ausdrücklich ankreuzen.

Bei jeder Neuerung erzeugen Sie sie frisch und laden sie ins GitHub-Verzeichnis; Ihre private Fassung bleibt unberührt.

      Seite ✎ öffnet den Editor: Sie schreiben direkt auf der Seite, wählen links Blöcke aus und speichern mit Strg+S. Verbinden Sie einmal den Ordner, dann schreibt der Editor direkt in die Datei und legt beim ersten Mal eine Sicherung .bak daneben.

      Änderungen liegen zunächst nur in diesem Browser. Index exportieren schreibt sie in eine neue index.html, die Sie über die alte legen.

      Für GitHub veröffentlichen

      Erzeugt eine öffentliche Fassung des Index zum Hochladen auf GitHub Pages: nur Ansehen, Mitlesen und Anhören — ohne Editor, ohne Aufnehmen, ohne Videodateien. YouTube-Verweise bleiben; welche Klangaufnahmen mitgehen, wählen Sie hier.

      Klangaufnahmen für die öffentliche Fassung

      MP3-Dateien sind fürs Netz gemacht; WAV-Dateien sind um ein Vielfaches größer und bei GitHub auf 100 MB je Datei begrenzt — sie sind darum nicht vorausgewählt. Jede angekreuzte Aufnahme müssen Sie zusammen mit dem Index in das GitHub-Verzeichnis hochladen, ebenso alle Liedseiten (HTML).

      Diese Dateien gehören ins GitHub-Verzeichnis

      So kommt die Sammlung ins Netz

      Einmalig: Bei github.com anmelden, ein neues öffentliches Repository anlegen (z. B. niggunim), dann unter Settings → Pages den Branch main mit Ordner / (root) wählen. Die Sammlung erscheint unter ihrname.github.io/niggunim.

      Bei jeder Neuerung: hier eine frische öffentliche index.html erzeugen und im Repository über „Add file → Upload files" die neue Fassung samt neuer Seiten und Aufnahmen hochladen — GitHub ersetzt gleichnamige Dateien. Ihre private index.html mit Editor und Aufnahme-Werkzeugen bleibt davon unberührt bei Ihnen.

      Zum Schutz: Die öffentliche Fassung kann grundsätzlich nichts verändern — auf GitHub Pages gibt es keinen Server, der Änderungen entgegennehmen könnte, und ein Passwort in einer offen einsehbaren Seite wäre nur Schein. Der echte Schlüssel zur Sammlung ist Ihr GitHub-Konto: nur wer dort angemeldet ist, kann die Dateien erneuern.

      Was gehört zusammen?

      Hinweise sind nur Vorschläge — in eine Playlist gelangt ausschließlich, was Sie hier ankreuzen und übernehmen.

      Der Schlüssel bleibt in diesem Browser und wird weder in den exportierten Index noch in die JSON-Sicherung geschrieben. Bei der Prüfung werden Titel, Beschreibungen, Schlagwörter und Abschnittsüberschriften Ihrer Niggunim an den gewählten Anbieter übertragen — die Aufnahmen selbst nicht.

      Niggun aufnehmen

      Legen Sie Seiten und Aufnahmen ab — HTML, WAV, MP3, MP4. Gleichnamige Dateien werden zu einer Karte zusammengelegt.
